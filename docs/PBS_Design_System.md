## 01. مبانی هویت بصری

### 1.1 شخصیت بصری

| ویژگی | معنای اجرایی |
|---|---|
| **Enterprise** | منظم، قابل ارائه در جلسه رسمی، دارای سلسله‌مراتب واضح |
| **Tech-forward** | معاصر و فنی، اما بدون افکت‌های تزئینی و غیرضروری |
| **Premium** | کیفیت از دقت اجرا و فضای سفید می‌آید، نه از شلوغی یا تجمل تصنعی |
| **Practical** | تصویرسازی مسئله، فرایند، خروجی و نتیجه مهم‌تر از شعار است |
| **Confident** | تیترهای روشن، کنتراست قوی و ادعاهای قابل دفاع |
| **Bilingual-ready** | هر قالب باید در RTL و LTR درست کار کند |

**سه کلمه راهنما:** دقیق · مدرن · قابل‌اعتماد  
**Three keywords:** Precise · Modern · Trustworthy

### 1.2 نسبت پیشنهادی استفاده از رنگ در یک صفحه

- **70–80٪** پس‌زمینه و سطوح خنثی (سرمه‌ای یا سفید / خاکستری خیلی روشن)
- **15–25٪** متن، ساختار، مرزها و لایه‌های مکمل
- **5–10٪** اکسنت سایان / آکوا برای نقاط کلیدی

این نسبت راهنمای بصری است، نه محدودیت ریاضی. سایان نباید به رنگ غالب همه اجزای صفحه تبدیل شود.

### 1.3 حالت وب‌سایت

1. **Light-only** — وب‌سایت عمومی، هدر، هیرو، سرویس‌ها، سناریوها، فرایند، اعتماد، هویت، پرسش‌ها و تماس همه روی سطح روشن ساخته می‌شوند.
2. **Deep closing** — فقط یک بلوک بیانیهٔ کوچک و بخش پایانی تماس/پاورقی از سرمه‌ای استفاده می‌کنند. این یک تم جایگزین نیست و قابل تغییر توسط کاربر یا سیستم‌عامل نیست.

**قاعده:** خوانایی و آرامش بصری اولویت دارد. صفحه نباید به نوارهای تیرهٔ متناوب تبدیل شود. سایان فقط نشانهٔ ساختاری کوچک است و متن سایان روی سفید مجاز نیست.

## 04. تایپوگرافی | Typography

### 4.1 خانواده‌های فونت

| زبان | فونت اصلی | جایگزین‌ها | کاربرد |
|---|---|---|---|
| فارسی | **Vazirmatn** | فونت سیستم با پشتیبانی فارسی؛ `Tahoma` در حالت fallback | وب‌سایت، اپ، پنل، محتوای متنی |
| انگلیسی | **Inter** | `Manrope`, `Arial`, system sans-serif | صفحات انگلیسی، داده، UI و پرزنتیشن |
| فارسی پریمیوم (اختیاری) | **Peyda** یا **IRANSansX** | فقط در صورت تهیه مجوز مناسب | کمپین و هدلاین برند، نه یک پیش‌فرض اجباری |
| کد / نمونه API | Monospace سیستم | `ui-monospace`, `monospace` | نمایش کد، شناسه‌ها و اعداد فنی |

**مجوز:** قبل از انتشار، مجوز استفاده فونت‌ها در وب، اپ، فایل خروجی و کاربرد تجاری بررسی شود. هیچ فایل فونتی بدون مجوز در دارایی‌های مشترک توزیع نشود.

### 4.2 مقیاس اندازه‌ها (Desktop)

| Token | Size / Line-height | Weight | کاربرد |
|---|---|---|---|
| `type.display` | `56px / 1.18` | 700–800 | هدر اصلی Hero |
| `type.h1` | `40px / 1.25` | 700 | عنوان صفحه |
| `type.h2` | `32px / 1.3` | 700 | عنوان سکشن |
| `type.h3` | `24px / 1.4` | 600–700 | عنوان کارت یا زیرسکشن |
| `type.h4` | `20px / 1.5` | 600 | زیرعنوان |
| `type.body-lg` | `18px / 1.8` | 400 | لید، پاراگراف معرفی |
| `type.body` | `16px / 1.8` | 400 | متن استاندارد فارسی |
| `type.small` | `14px / 1.65` | 400–500 | توضیح کوتاه، Label |
| `type.caption` | `12px / 1.6` | 400–500 | فقط داده غیرحیاتی یا محدود |

- در **موبایل**: `display = 36px`، `h1 = 30px`، `h2 = 26px`، `h3 = 21px`؛ متن عادی ترجیحاً 16px باقی بماند.
- متن فارسی به ارتفاع خط بیشتری از انگلیسی نیاز دارد؛ `body` حدود `1.7–1.9` و انگلیسی معمولاً `1.5–1.65`.
- برای تیترهای انگلیسی، فاصله حروف اندک منفی می‌تواند مناسب باشد؛ برای فارسی از letter-spacing مصنوعی خودداری شود.
- تیترها کوتاه، صریح و به‌دور از طول زیاد باشند. برای متن‌های بلند، عرض خواندن حدود `60–75ch` با بررسی نمایش فارسی مناسب است.

### 4.3 اعداد و زبان

- صفحه فارسی: متن راست‌چین و `dir="rtl"`؛ تاریخ، آدرس سایت، ایمیل، کد، تلفن و قیمت با جهت‌گذاری محلی درست نمایش داده شوند.
- صفحه انگلیسی: `lang="en"` و `dir="ltr"`؛ چینش باید واقعاً آینه‌ای و بومی باشد، نه ترجمه در قالب RTL.
- از CSS منطقی مانند `margin-inline-start` و `padding-inline-end` استفاده شود، نه وابستگی دائمی به `left/right`.
- نمایش اعداد در گزارش، صورت‌حساب و قرارداد باید سازگار با مخاطب و قالب سند باشد؛ هنگام کپی مقادیر فنی به سیستم‌های دیگر، اعداد لاتین قابل استفاده بمانند.

### 5.2 Grid و Breakpoint

| Context | پیشنهاد |
|---|---|
| `container.max` | `1200px` (برای محتوا، نه لزوماً عناصر تمام‌عرض) |
| `container.article` | `760px` |
| Mobile | تا `639px`؛ تک‌ستونی با padding افقی `20px` |
| Tablet | `640–1023px`؛ شبکه 2 ستونی در صورت نیاز |
| Desktop | `1024–1439px`؛ شبکه 12 ستونی، gutter حدود `24px` |
| Wide | از `1440px`؛ محتوا در max-width کنترل شود |
| Card gap | `16–24px` |

از طراحی **Mobile-first** شروع کنید. UI نباید روی پهنای 320px با اسکرول افقیِ ناخواسته بشکند. نقطه‌های شکست به محتوا وابسته‌اند، نه فقط به نوع دستگاه.

### 5.3 Radius و Border

| Token | مقدار | کاربرد |
|---|---|---|
| `radius.sm` | `8px` | Tag و کنترل کوچک |
| `radius.md` | `12px` | دکمه، input و فیلد |
| `radius.lg` | `16px` | کارت معمولی |
| `radius.xl` | `24px` | پنل شاخص، Hero card |
| `radius.pill` | `999px` | Badge و تراشه‌های گرد |
| `border.width.default` | `1px` | مرز معمولی |
| `border.width.strong` | `2px` | تاکید / Focus |

به‌جز آواتار و Badge، گردی بیش از حد را به هویت غالب PBS تبدیل نکنید.

### 5.4 سایه‌ها | Shadows

```css
--shadow-xs: 0 1px 2px rgb(16 24 40 / 5%);
--shadow-sm: 0 4px 10px rgb(16 24 40 / 8%);
--shadow-md: 0 10px 20px rgb(16 24 40 / 10%);
--shadow-lg: 0 20px 40px rgb(16 24 40 / 12%);
```

روی دارک بیشتر از Border و تغییر سطح استفاده شود؛ سایه‌های سنگین سیاه معمولاً ارزش خوانایی ندارند.

## 06. Motion و Interaction

| Token | مقدار |
|---|---|
| `motion.fast` | `150ms` |
| `motion.normal` | `250ms` |
| `motion.slow` | `400ms` |
| `motion.ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` |

- حرکت باید بیانگر پاسخ سیستم باشد: Hover، Focus، بازشدن منو و انتقال‌های کوتاه. مرورگر نباید محتوای اصلی را پشت scroll reveal پنهان کند.
- انیمیشن ورودی فقط در حد یک fade کوتاه برای منو یا ابزار تعاملی است؛ بدون حرکت‌های شدید یا Scroll-jacking.
- Hover ردیف یا کارت می‌تواند جابه‌جایی حداکثر `2–4px` یا تغییر ظریف Border داشته باشد.
- برای `prefers-reduced-motion: reduce`، انیمیشن‌های غیرضروری حذف شوند.
- سایت PBS فرم ارسال پیام ندارد؛ Loading/Error/Success فقط برای کنترل‌هایی معنا دارد که واقعاً وجود دارند.

## 07. کامپوننت‌ها | Component Standards

### 7.1 Buttons

| Variant | Light website | استفاده |
|---|---|---|
| Primary | Navy + متن سفید | اقدام اصلی و یکتا |
| Secondary | سفید + Border Navy | اقدام مکمل |
| Tertiary | بدون زمینه، متن Navy | لینک کم‌اولویت |
| Danger | پس‌زمینه / متن متناسب با Error | عملیات تخریبی |

نسخهٔ دکمه روی سطح تیره فقط برای کاربردهای برند بیرون از وب یا در صورت افزودن فرم به بخش تماس استفاده شود؛ وب فعلی فقط دکمه‌های روشن دارد.

- ارتفاع پیشنهادی دکمه: `44–48px`؛ در موبایل ناحیه تعامل حداقل حدود `44×44px`.
- Label فعل‌محور: «درخواست مشاوره»، «مشاهده خدمات»، «ارسال درخواست» / `Request a Consultation`, `Explore Services`.
- در هر بخش، یک CTA اصلی بر بقیه غالب باشد؛ برای بازدیدکننده فشار بصری چند CTA مساوی ایجاد نشود.

### 7.2 Inputs و فرم‌ها

- Label واقعی بالای فیلد؛ Placeholder به‌تنهایی جای Label را نمی‌گیرد.
- Border پیش‌فرض ملایم، Focus قابل مشاهده، متن خطای واضح زیر فیلد.
- فرم‌های جذب لید تا حد امکان کوتاه باشند: نام، راه ارتباطی، نیاز اصلی؛ اطلاعات اضافی فقط در صورت ضرورت.
- فرم فارسی RTL؛ ایمیل، URL و شماره تلفن داخل فیلد با `dir="ltr"` در صورت نیاز.
- توضیح حریم خصوصی هنگام گرفتن اطلاعات شخصی، متناسب با قوانین بازار هدف ارائه شود.

### 7.3 Cards

- شعاع اصلی `16px`، Padding حدود `24px` و Border 1px ظریف.
- ساختار ثابت: Icon/Visual → Title → توضیح → اقدام.
- ارتفاع و فاصله در کارت‌های هم‌سطح منظم باشد؛ طول متن را پیش از طراحی کنترل کنید.
- کارت‌ها نباید فقط به‌دلیل سایه سنگین شبیه کلیک‌پذیر شوند؛ نشانه تعاملی واضح باشد.

### 7.4 Navigation

- منوی اصلی سایت فارسی: **خدمات | روش کار | چرا PBS | پرسش‌ها** و CTA «درباره پروژه صحبت کنیم». پاورقی «نمونه‌کارها» و «تماس» را پوشش می‌دهد.
- نسخه انگلیسی: **Services | Process | Why PBS | FAQ** و CTA `Discuss a project`.
- زبان‌گردان واضح: `FA / EN`؛ از پرچم برای نمایش زبان استفاده نشود. زبان‌گردان یک کنترل دوبخشی با حالت فعال Navy است.
- هدر چسبانِ روشن و کم‌ارتفاع با یک لایهٔ شیشه‌ای محدود و fallback توپر؛ منوی موبایل با Focus مدیریت‌شده و قابل استفاده با کیبورد طراحی شود.

### 7.5 Icons, Charts & Data

- آیکن‌های Line با stroke تقریباً 1.75–2px؛ اندازه‌های استاندارد `16/20/24px`.
- یک خانواده آیکن واحد انتخاب شود (مثل Lucide)؛ ترکیب چند استایل متفاوت ممنوع.
- نمودارها: Navy برای سری اصلی روی لایت، Cyan روی دارک؛ Mint فقط سری کمکی و با رعایت کنتراست.

### 8.1 اجزای هویتی موجود

### 8.2 قواعد اجرایی

1. نسخهٔ کامل لوگو برای هدر، صفحه اول و اسناد رسمی برند استفاده شود. هدر وب از نسخهٔ on-light و پاورقی از نسخهٔ primary-dark استفاده می‌کند.
2. بازطراحی آزاد فرم حروف PBS، تغییر جرقه یا برش دلخواه اجزای لوگو مجاز نیست.
3. روی پس‌زمینهٔ روشن از نسخهٔ تأییدشدهٔ on-light استفاده شود؛ نیاز به پلاک سرمه‌ای یا فیلتر رنگ نیست.
4. نسبت تصویر ثابت بماند؛ کشیدن افقی/عمودی، Rotate، Gradient جدید، Glow شدید و Outline دلخواه ممنوع.
5. **Clear space پیشنهادی:** حداقل فاصله‌ای هم‌ارز نصف ارتفاع حروف `PBS` در اطراف لوگو؛ بعد از دریافت فایل وکتور قابل نهایی‌سازی است.
6. **حداقل عرض پیشنهادی وردمارک دیجیتال:** `120px`؛ هدر وب بین ۱۲۰ تا ۱۴۸ پیکسل و در موبایل متناسب با همان حداقل استفاده می‌شود. برای Favicon نسخه ویژه لازم است.
7. تغییر املای PBS یا نوشتن `P.B.S.` به‌عنوان لوگوی اصلی توصیه نمی‌شود.

- **Technical detail:** خطوط شبکه فقط درون یک دیاگرام مشخص، نه به‌عنوان پس‌زمینهٔ کل صفحه.
- **Brand Gradient (اختیاری، بیرون از وب):** `linear-gradient(135deg, #041633 0%, #062B73 100%)`.

## 12. استاندارد طراحی وب‌سایت PBS

### 12.1 ساختار صفحه اصلی

1. **Hero:** چه کاری، برای چه تیم‌هایی، و قدم بعدی؛ همراه با یک نقشهٔ مفهومی از دامنهٔ کار و CTA اصلی.
2. **Services:** چهار خانوادهٔ وب‌سایت/لندینگ، پنل و نرم‌افزار، اتوماسیون/یکپارچه‌سازی و اجرای محدود رشد؛ همراه با مسئله، تحویل و مرز دامنه.
3. **Scenarios:** موقعیت‌های نمونه با خروجی پیشنهادی، صریحاً به‌عنوان سناریوی نمونه و نه مطالعهٔ موردی.
4. **Process:** شناخت → محدوده → ساخت → بازبینی و تحویل؛ فقط یک بار در کل صفحه.
5. **Principles:** اعتماد از روش کار، ظرفیت واقعی و مرزهای شفاف، نه ادعای سابقه.
6. **Identity aside:** توضیح کوتاه نام PBS؛ جایگزین بلوک بزرگ و تکراری معرفی برند.
7. **FAQ:** محدوده، قیمت‌گذاری، نمونه‌کار، وضعیت حقوقی، زمان‌بندی و پشتیبانی.
8. **Contact/Footer:** دعوت نهایی به گفتگو، کانال‌های تأییدشده یا وضعیت صادقانهٔ «به‌زودی»، سپس پاورقی سرمه‌ای.

### 12.2 الگوهای تعامل

- نوار ناوبری واضح، دکمه‌های ثابت از نظر ظاهر، کنتراست مناسب؛ هدر چسبانِ روشن با fallback توپر.
- تصاویر بهینه‌شده، Lazy Loading و فونت‌های زیرمجموعه‌سازی‌شده (subset) در صورت امکان.
- هدف عملکرد: تجربه روان موبایل، کمترین وابستگی غیرضروری به سرویس‌های خارجی و سنجش واقعی Core Web Vitals.
- رابط قابل استفاده با کیبورد، Focus قابل مشاهده، متن جایگزین معنادار و هدف‌گذاری WCAG 2.2 AA برای صفحات کلیدی.
- تم **فقط روشن** است؛ درخواست سیستم‌عامل برای حالت تاریک نباید ظاهر را تغییر دهد. هیچ scroll reveal یا محتوای پنهان پشت انیمیشن وجود ندارد.
- CTAهای تماس فقط لینک‌های تأییدشدهٔ بیرونی یا وضعیت صادقانهٔ «به‌زودی» هستند؛ فرم ساختگی، پیام موفقیت جعلی یا شمارهٔ حدسی وجود ندارد.
- صفحه فارسی و انگلیسی باید محتوای محلی‌سازی‌شده داشته باشند؛ صفحه انگلیسی با Claim ساختگی درباره حضور بین‌المللی ساخته نشود.

## 14. نسخه انگلیسی کوتاه | English Brand Design Brief

**Brand:** PBS — Practical Business Solutions  
**Design direction:** Enterprise Tech Minimal  
**Visual personality:** Professional, precise, trustworthy, modern and practical.  
**Primary palette:** PBS Navy `#062B73`, Deep Midnight `#041633`, Electric Cyan `#33D6E8`, Aqua Mint `#6EF2D6`.  
**Theme strategy:** The public website is light-only. Deep Midnight and Navy are reserved for the single closing contact/footer statement and small brand surfaces; there is no theme toggle and no OS-dark variant on the web.

**Bilingual requirements:** Native RTL for Persian and native LTR for English. Localize copy, dates, contact methods and layouts rather than mirroring text only.  
**Avoid:** Loud neon gradients, excessive glassmorphism, stock imagery implying fictional clients, fabricated statistics, cluttered layouts and claims of an incorporated organization without substantiation.
